## 🏗️ CORE ARCHITECTURE PATTERNS

### 1. Transactional DOD Kernel (v0.1.4 ✨)
**3-Phase execution**:
```
PHASE_COLLECT → read buffers, enqueue commands
PHASE_RESOLVE → atomic mutations, emit events  
AUDIT        → shadow buffer validation (debug)
```
**Modules**: `KernelStateHash.ts`, `DODBufferProxy.ts`, `KernelAuditSystem.ts`, `TransactionalKernelMode.ts`

### 2. Event-Driven Systems
Combat → `DamageApplied` event → `HUDSyncSystem` listens → UI updates (zero coupling)

### 3. Snapshot-Based Replication
Server captures kernel state every tick → broadcasts to clients → clients deserialize + apply

### 4. SystemContext Injection
All systems use `systemContext.getSystem(HealthSystem)` instead of global engine

### 5. Domain Facades
Cohesive APIs like `CombatFacade` instead of reaching across rendering/UI/gameplay

## 🎓 COMMON WORKFLOWS

### ❓ "I want to add a new gameplay system"
1. Create `client/src/engine/systems/YourSystem.ts` (extends `GameSystem`)
2. Implement `update(dt)` method
3. Register in bootstrap assembly
4. Add EventBus emissions for communication
5. `npm run audit:engine` validates health

### ❓ "I need to fix a multiplayer bug"
1. Check `server/data/runtime_metrics/` for session timeline
2. Look at `NetworkSyncSystem` (client authority) + `server/src/session/` (server authority)
3. Add console logs to both sides
4. Verify with multiplayer test: 2 browsers joining same room

### ❓ "Performance is slow, where's the bottleneck?"
1. Open DevTools Performance tab
2. Record 10 seconds, check flame chart
3. Compare against `engine/reports/ENGINE_PERFORMANCE_BUDGET.md` baseline
4. Profile slow system in isolation

### ❓ "A commit broke something, what was it?"
1. Check `npm run type-check` + `npm run audit:engine` outputs
2. Look at `RuntimeDiagnosticsCoordinator` debug panel (in-game)
3. Check `engine/reports/` for health regression
4. Review git diff of audit health score
